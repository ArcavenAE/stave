# spec/

The vendored Wiz GraphQL schema, and nothing else.

| File | What it is |
|---|---|
| `wiz-schema.graphql` | The tenant schema as SDL, printed from a live introspection response by `cargo xtask sync-spec`. |
| `wiz-schema.graphql.sha256` | Pin over the SDL bytes. |

Both are absent until a Wiz service account exists: introspection needs
tenant credentials. `cargo xtask check-ops` reports that and exits 0
while the schema is missing, so CI stays green and the curated
documents in `crates/stave-api/ops/` are simply marked unvalidated.

## Working with it

```sh
cargo xtask sync-spec    # introspect the tenant, refresh both files
cargo xtask check-ops    # validate every curated document against the schema
```

The SDL is printed deterministically (types, fields, arguments, enum
values, interfaces, and union members sorted by name) so a server-side
reordering cannot move the pin and review diffs stay readable.
Descriptions are dropped; `@deprecated` markers are kept, and
`check-ops` warns when a curated document selects a deprecated field.

Never hand-edit either file. The schema is generated, and the pin is
over the generated bytes.

## Hygiene

The schema is type structure only: no tenant identity, no cloud
account or resource identifiers, no findings. The endpoint it was
fetched from stays in local config and is never written here. Anything
you add to this directory is subject to
`.claude/rules/tenant-data-hygiene.md`, so use placeholders
(`https://api.<region>.app.wiz.io/graphql`) in prose.
