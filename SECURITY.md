# Security Policy

## Reporting a Vulnerability

If you believe you've found a security vulnerability in stave, please
report it privately via [GitHub Security
Advisories](https://github.com/ArcavenAE/stave/security/advisories/new).

We aim to acknowledge reports within 72 hours and to coordinate disclosure
once a fix is available.

## Scope

stave is a local CLI that talks to the Wiz API. Vulnerabilities in
Wiz's service itself should be reported to Wiz, Inc. directly, not
here.

In-scope examples:

- Credential mishandling (token leakage to logs, audit trail, error output)
- Audit-trail redaction failures (sensitive fields not stripped)
- Supply-chain issues in stave's dependency graph

## Tenant Data Hygiene

stave's entire subject matter is a live Wiz tenant watching real cloud
estates. Payloads and even metadata identify them. Treat ALL of the
following as confidential tenant data — never paste it into issues,
PRs, commits, discussions, or public logs:

- **Resource payloads** — cloud account/subscription IDs, ARNs,
  resource names and IDs, hostnames, IP addresses, user names/emails.
- **Posture and findings** — issues, vulnerability-to-resource
  mappings, attack-path output, misconfiguration details naming real
  resources. Read-only is not the same as non-sensitive: a findings
  export is a targeting map of the estate.
- **Audit-trail lines** — they carry real query variable values,
  pagination cursors, your local hostname/username, and CEL predicate
  text.
- **The tenant identity itself** — the tenant ID (GUID), the
  region-bearing `api.<region>.app.wiz.io` hostname, and the registry
  username (it embeds the tenant ID).

Defenses in this repo:

- `scripts/check-tenant-leaks.sh` runs in pre-commit (lefthook) and CI
  with publishable generic patterns; add your tenant's literals to a
  gitignored `.leak-patterns.local` for local enforcement.
- GitHub secret scanning + push protection are enabled on the repo.
- Fixtures under `examples/fixtures/` are synthetic by policy — never
  regenerated by copying live payloads (see `examples/README.md`).
- `STAVE_AUDIT=off` disables the trail for a session;
  `STAVE_AUDIT_DIR` relocates it. The trail lives outside any repo
  by default (`~/.stave/audit/` on macOS,
  `~/.local/state/stave/audit/` on Linux).

When reporting a stave bug, follow the sanitization checklist in
CONTRIBUTING.md and the issue template.

## Audit Trail Privacy

stave writes a local JSONL audit trail of every API call. By design
this trail strips authentication tokens and known sensitive payload
fields before writing. See `docs/audit-trail-format.md` for the
redaction policy. Report any field that leaks via the channel above.
